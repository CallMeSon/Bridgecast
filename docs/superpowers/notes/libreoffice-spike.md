# LibreOffice Linux spike: results (2026-10-31)

Scope: Task 1 of `docs/superpowers/plans/2026-10-27-libreoffice-linux.md`. Throwaway code stayed in the scratchpad (not committed). **Gate (step 2) passed**: a `desktopCapturer` source `window:<xid>:0` of the LibreOffice slideshow window plays in Electron while another window covers it.

Environment: Zorin OS (GNOME, **Wayland session with XWayland**, `XDG_SESSION_TYPE=wayland`, `DISPLAY=:0`), single 1920x1080 display, LibreOffice 26.2.6.3, `python3-uno`, Electron 45.0.0, PipeWire (pipewire-pulse). Fixture: `fixtures/sample-anim.pptx` did not exist; it was generated with python-pptx by `scripts/make-sample-anim.py` (6 slides: 3 click bullets; click + after-previous; Dissolve transition; hidden slide; video with sound that autoplays; plain slide with a font that is not installed). It is a stand-in, not the PowerPoint-made file the native plan asked for.

## Findings that change the plan

1. **A hidden (`Hidden=True`) document cannot start a slideshow.** `presentation.start()` returns but `getController()` stays `None`. Open the document visible (`Hidden=False`) for slideshows and keep `Hidden=True` only for the import. `frame.getContainerWindow().setVisible(False)` after load unmaps the window (no capture), so it is not an option for a show.
2. **Windowed mode (`IsFullScreen=False`) plays inside the Impress document window**, there is no separate slideshow window. The capture target is the document frame's container window, and that window carries the menu bar and toolbars. `frame.LayoutManager.setVisible(False)` hides them (re-apply after `start()` and after slide changes; one capture showed the menu bar again). The window is clamped by the window manager: 1920x992 here for a 1920x1080 screen, positioned at y=36; the slide is letterboxed inside it. The window size is therefore not exactly the Canvas; `StreamLayer` scales it. A window cannot be moved off screen on a single display (mutter clamps it); keep it behind the other windows.
3. **The XID.** `XSystemDependentWindowPeer.getWindowHandle(ByteSequence(b''), SYSTEM_XWINDOW)` works on `frame.getContainerWindow()` and returns a struct `SystemDependentXWindow { WindowHandle, DisplayPointer }`; `WindowHandle` is the XID and equals the id in `xwininfo` and in the `desktopCapturer` source `window:<xid>:0`. Use the client window id (class `libreoffice`), not the `mutter-x11-frames` parent that has the same title.
4. **VCL plugin: use `SAL_USE_VCLPLUGIN=gen` (plus `GDK_BACKEND=x11`).** With the default `gtk3` plugin LibreOffice **deadlocks (futex, all UNO calls hang forever) when a video on the current slide reaches its end**; calls issued while the video still plays are fine. With `gen` there is no hang and the XID call works. `gen` also gives X11 windows under a Wayland session. Without `GDK_BACKEND=x11` (gtk3) the window is a native Wayland surface and has no XID at all.
5. **Electron must run as an X11 client and must think the session is X11.** On this Wayland session `desktopCapturer` goes to the PipeWire portal (`window:1:0:s`, ScreenCastPortal fails) even with `--ozone-platform=x11`. Starting Electron with `XDG_SESSION_TYPE=x11 WAYLAND_DISPLAY=` and `--ozone-platform=x11` lists real X11 windows (`window:12582935:0 sample-anim.pptx — LibreOffice Impress`). So "capture works" is a property of how the app is started, not of the compositor. The plan's Wayland rule (`canCapture = sessionType !== 'wayland'`) is kept as the safe default because nobody has run the app that way; see Open points.
6. **The mouse pointer is part of the capture** when it is over the LibreOffice window (visible in the test frame). Not solved here. Needs the window to sit where the pointer does not go (second display) or a cursor-less capture; field test.
7. **Video pictures are not captured; their sound is.** The video shape is drawn by GStreamer in a child X window (`777x440` child of the Impress window); the composite capture shows the slide without the video. The slide frame, text and animations are captured fine. A deck with a video is therefore a risk on air (the picture is missing, the sound plays). The plan's static detection already treats `MediaShape` as non static; the product decision (e.g. warn, or default such decks to Still images) is left to the user, see Open points.
8. **Pulse: Chromium does not list `.monitor` sources** in `enumerateDevices`, so `getUserMedia({audio:{deviceId}})` on `pptshare_lo.monitor` is impossible. Fix: after the null sink, `pactl load-module module-remap-source master=pptshare_lo.monitor source_name=pptshare_lo_input source_properties=device.description=pptshare_lo_input`. The remap source is listed as audioinput with label `pptshare_lo_input` (contains `pptshare_lo`, so the plan's `findMonitor` rule works) and delivers the sound (peak 0.13 for the 440 Hz test clip). The sink input of LibreOffice went to the null sink (`PULSE_SINK=pptshare_lo`), nothing to the speakers. `PulseSink` must load and unload both modules (remember both module ids; never unload by module name, that removes every null sink of the user).
9. **`soffice` is a wrapper**: the pid of the spawned process ends right after start and `oosplash`/`soffice.bin` keep running. To kill "only the instance the app started", find the process by its unique `--accept=pipe,name=pptshare-<pid>` argument in `/proc/*/cmdline`.

## Step by step

- Step 1: start with the app flags and a scratch profile: connects over the pipe in about 1.2 s; opening the 6-slide file takes 0.3 s. Slideshow start needs a visible frame (finding 1). Presentation properties `IsFullScreen/IsMouseVisible/IsEndless/StartWithNavigator/UsePen` can all be set. `_NET_WM_STATE_SKIP_TASKBAR` was set with `xprop`; the bridge should set it with `xprop`/`xdotool` if present (best effort), the plan asks for it.
- Step 2 (gate): PASSED with the conditions in finding 5. Captured size 1920x992.
- Step 3: `gotoNextEffect` returns in about 1 ms; effects play asynchronously. Counts: slide 0 needs 3 next calls and the 4th moves to slide 1; slide 1: click, then the After Previous effect plays by itself (one call), next call changes slide; slide 2 (transition) one call; the hidden slide 3 is skipped by `gotoNextEffect`; `gotoSlideIndex(3)` still goes to it explicitly. After the last slide one more `gotoNextEffect` goes to the "click to exit" pause and the next ends the show (`isRunning` false, controller index -1): the bridge must never send a `next` past the last step (the manager does not) and must restart the show if it ended. `gotoPreviousEffect` from step 0 of slide 2 lands on slide 1 with all its effects done (listener `slideEnded(reverse=true)`), a second previous goes back one effect inside slide 1; previous at the first slide stays. `XSlideShowListener` gives `slideEnded(reverse)`, `slideTransitionStarted`, `slideAnimationsEnded`, `paused`, begin/end events per animation node: the slide change (`slideEnded`) is the reliable signal to resync the step counter; the index is read with `getCurrentSlideIndex()`.
- Step 4: see findings 8 and 4.
- Step 5: PDF with hidden slides: `storeToURL` with `impress_pdf_Export` and `FilterData ExportHiddenSlides=True`: 6 pages for 6 slides, 0.07 s. Notes from the notes page `NotesShape` text. `Visible` is `False` for the hidden slide. Clicks: walk `page.getAnimationNode()`; each node has `UserData` `node-type` (EffectNodeType): `1` ON_CLICK, `3` AFTER_PREVIOUS, `2` WITH_PREVIOUS, `6` INTERACTIVE_SEQUENCE; counting `node-type == 1` gave 3, 1, 0, 0, 0, 0 (matches the fixture). The media autoplay on slide 4 imported as a node without a node-type (clicks 0). `TransitionType` 37 (Dissolve) on the transition slide, 0 elsewhere. `MediaShape` is reported by `getShapeType()`. Two documents can run a slideshow at the same time in one instance (both `isRunning`), each with its own window and XID.
- Latency/CPU: UNO round trip about 1 ms; idle soffice about 6 % CPU while a slideshow is open. Not measured under a real show.
