# PPT Share Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aplikasi desktop Windows yang menyimpan deck PPT/PDF per event dan memancarkan satu output NDI yang dikontrol lewat Next/Prev, Freeze, dan Black.

**Architecture:** Proses main memegang state (library di disk + `ProgramState`) dan reducer murni. Jendela operator (React) hanya mengirim action lewat IPC dan menampilkan state. Jendela output tersembunyi (offscreen) merender slide Program; frame `paint`-nya dikirim ke NDI lewat antarmuka `NdiSender`. Slide disimpan sebagai PNG hasil konversi saat import.

**Tech Stack:** Electron, TypeScript, React, Vite (electron-vite), Vitest, pdfjs-dist, PowerShell + PowerPoint COM, library NDI (dipilih di Task 8), electron-builder.

**Spec:** `docs/superpowers/specs/2026-10-06-ppt-share-design.md`. UI acuan: `design/mockup.html`.

## Global Constraints

- Windows 11, PowerPoint dan NDI Tools sudah terinstal di PC target. Aplikasi harus berjalan tanpa internet (font Geist dan ikon Phosphor dibundel lokal, bukan dari CDN).
- Satu output NDI saja. Tidak ada output kedua, speaker view, atau transcript.
- Tidak ada konsep Preview/Program terpisah: Next/Prev langsung mengubah Program.
- Pintasan: `Space` dan `→` Next, `←` Prev, `F` Freeze, `B` Black. Tidak aktif saat fokus ada di input teks.
- Teks UI berbahasa Indonesia. Tema light dan dark, dark default, pilihan disimpan.
- Satu warna aksen. Radius 8px untuk kontrol, 12px untuk panel.
- Import PNG pada lebar 1920 px; tinggi mengikuti rasio slide asli.
- Setiap error ke pengguna menyebut masalah dan tindakan pemulihan (contoh: "Tidak bisa membuka file. Tutup file di PowerPoint lalu coba lagi.").

## Review Focus

1. Slide diekspor PowerPoint bernama `Slide1.PNG … Slide10.PNG`; urutan alfabet menaruh Slide10 sebelum Slide2. Urutan harus numerik. (Task 4)
2. PowerPoint sudah terbuka dengan file lain milik operator. Aplikasi tidak boleh menutup PowerPoint atau file itu. (Task 4)
3. Deck 4:3 atau rasio bukan 16:9. Slide harus tampil utuh dengan bar hitam, tidak terpotong atau melar. (Task 4, 7)
4. Deck yang sedang tampil di output dihapus atau diurutkan ulang saat live. Output tidak boleh menampilkan gambar rusak. (Task 2, 3)
5. Slide statis tidak menghasilkan event `paint`, sehingga receiver NDI melihat sumber "mati". Frame terakhir harus dikirim ulang sesuai fps. (Task 7)

- Aturan: `decks` berurutan sesuai event. Saat `frozen === false`, setiap perubahan posisi (`deckId`,`index`) juga mengubah `shown`. Saat `frozen === true`, posisi berubah tapi `shown` tetap.

- [ ] **Step 1:** Tulis tes dengan dua deck (A: 3 slide, B: 2 slide):
  - `next` dari A/0 menghasilkan A/1 dan `shown` = A/1.
  - `next` di A/2 pindah ke B/0; `next` di B/1 tidak mengubah state.
  - `prev` di B/0 pindah ke A/2; `prev` di A/0 tidak mengubah state.
  - Dengan `frozen:true`, `next` mengubah posisi tapi `shown` tetap; `toggleFreeze` dimatikan lalu `next` membuat `shown` mengikuti posisi.
  - `toggleBlack` tidak mengubah posisi maupun `shown`.
  - `goto` dengan index di luar rentang diabaikan; `selectDeck` dengan id tidak dikenal diabaikan.
  - `selectDeck` memindah posisi ke deckId/0.
  - Dengan `decks = []`, `next/prev/goto/selectDeck` tidak mengubah state dan `toggleFreeze/toggleBlack` tetap bekerja.
  - `reconcile` setelah deck yang sedang `shown` dihapus mengembalikan `shown: null`; bila `deckId` hilang, posisi pindah ke deck pertama (index 0) atau `null` jika kosong; bila index melebihi jumlah slide, index dijepit ke slide terakhir.
