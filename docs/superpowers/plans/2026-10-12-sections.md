# Sections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optional sections that split an event's deck list. Auto advance stops at a section boundary. `N` / `Shift+N` and buttons jump to the next or previous section.

**Architecture:** `EventMeta.sections` holds dividers as `{ id, name, at }` over the unchanged `deckIds`. Pure helpers in `src/shared/sections.ts` convert between that and a mixed order list, and split decks into segments. The reducer, main library, IPC and renderer all use those helpers. The reducer gets `sections` as a new optional argument, so callers without sections keep today's behaviour.

**Tech Stack:** Electron, TypeScript, React, Vitest, e2e in `e2e/smoke.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-12-sections-design.md`

## Global Constraints

- UI language English. Label is "Section" ("SECTION" small caps on the row, "Next section", "Prev section", "Add section", "Add section above", "Remove section", "End of section", "End of event").
- Section names: trimmed, not empty, no `\p{Cc}\p{Cf}`, at most `DECK_NAME_MAX` (120) code points. Default name `Section N`, N = number of sections + 1.
- Event without sections (field absent or `[]`) behaves exactly as before. Every existing test must still pass unchanged.
- Every user-facing error names the problem and the recovery action (pattern of existing messages in `src/main/library.ts`).
- Shortcuts: `N` = `nextSection`, `Shift+N` = `prevSection`, ignored while typing and on key repeat, like the others.
- Section jumps go live through `moveTo` (as `selectDeck`). While frozen they only move the position.
- Commands: `npm test`, `npm run typecheck`, `npm run lint`, `npm run test:e2e`.

## Review Focus

1. Removing the last deck of a section leaves an empty section. `N` must skip it, not stop on it (test in Task 2).
2. Two sections next to each other, or a section dragged to the very top (`at = 0`), must round-trip through `orderItems`/`splitOrder` without losing or reordering sections (test in Task 1).
3. The live deck is dragged into another section mid-show. The next Next must use the new boundary, because the reducer reads current sections on every dispatch (test in Task 4).
4. A reorder sent by a stale renderer (a deck was imported meanwhile) must be refused, with nothing changed (test in Task 3).
5. With Caps Lock on, `N` arrives as `key: 'N'` without Shift. It must still mean Next section, so decide by `shiftKey`, not by case (test in Task 5).

### Task 1: Shared section helpers

**Files:**
- Create: `src/shared/sections.ts`
- Create: `src/shared/sections.test.ts`
- Modify: `src/shared/types.ts` (add `SectionMeta`, `EventMeta.sections?`)

**Interfaces:**
- Produces:
  - `types.ts`: `export interface SectionMeta { id: string; name: string; at: number }` and `EventMeta.sections?: SectionMeta[]` (JSDoc: "Dividers over deckIds: a section starts before deckIds[at]. Absent = no sections.").
  - `sections.ts`:
    - `export type OrderItem = { deck: string } | { section: string }`
    - `export function orderItems(deckIds: string[], sections: SectionMeta[] = []): OrderItem[]`: sections with the same `at` keep their array order, placed before `deckIds[at]`. `at = length` goes at the end.
    - `export function splitOrder(items: OrderItem[], sections: SectionMeta[]): { deckIds: string[]; sections: SectionMeta[] }`: `at` is recomputed from each section's position, and the result is in item order. Names and ids come from `sections`. It does not validate (callers validate).
    - `export function sanitizeSections(raw: unknown, deckCount: number): SectionMeta[]`: drops entries that are not objects, have a non-string or duplicate id, or have an empty or non-string name. Clamps `at` to integer `0..deckCount`, then stable-sorts by `at`.
    - `export interface Segment<D> { section: SectionMeta | null; decks: D[] }`
    - `export function segmentsOf<D>(decks: D[], sections: SectionMeta[] = []): Segment<D>[]`: the leading block (`section: null`) comes first, only if non-empty. Every section produces a segment, even an empty one. `decks` are in `deckIds` order.

- [ ] **Step 1: Write failing tests** in `src/shared/sections.test.ts`:
  - `orderItems(['a','b','c'], [{id:'s1',name:'One',at:1}])` → `[{deck:'a'},{section:'s1'},{deck:'b'},{deck:'c'}]`
  - adjacent and edge: sections `at` 0, 2, 2, 3 over 3 decks → `s0,a,b,s1,s2,c,s3`. Then `splitOrder` of that result returns the same `deckIds` and the same sections with the same `at` (round trip).
  - `splitOrder([{section:'s1'},{deck:'a'},{deck:'b'},{deck:'c'}], [s1 at 1])` (deck a moved below s1) → `deckIds ['a','b','c']`, `s1.at` 0. `splitOrder([{deck:'a'},{deck:'b'},{section:'s1'},{deck:'c'}], …)` → `s1.at` 2.

  - `segmentsOf(['a','b','c'], [])` → one segment `{section:null, decks:[a,b,c]}`. With `s1 at 1` → `[null:[a]], [s1:[b,c]]`. With `s1 at 0` → only `[s1:[a,b,c]]`. Empty section in the middle → segment with `decks: []`.
