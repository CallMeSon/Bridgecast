## 1. Behaviour

- **Onboarding (3 cards):** Welcome, Why Bridgecast, Get started. Shown centred in a dialog-style card over a 45% scrim. Keys: Enter or Next to go on, Back to go back, Escape or Skip to close.
- **Spotlights (3 steps, real app):** each step rings a real control with a 2px Text ring and puts a tooltip next to it.
  1. Home: "New event" (`data-testid=home-new`). Shown when Home is the view.
  2. Console: "Add files" in the Decks panel (`Library.tsx` footer, line ~1420). Shown the first time an event is open in the console.
  3. Browser: the Add web page dialog (`AddWebDialog.tsx`). Shown when that dialog opens.
- Spotlight steps wait for their target. If the operator does not reach a step, the tour stays on the last step it showed and offers Skip. It never forces a view change.
- **Keys while the tour is open:** the tour owns the keyboard. Space, arrows, F, B, K and N must not take slides to air or change the Program. `App.tsx` already has a guard (`viewRef.current === 'home'` and `keysClaimed()`); add `tourOpen` to that guard.
- **Motion:** the card rises 8px with opacity over 0.18s; the spotlight ring and tooltip move between steps over 0.18s (transform and opacity). Under Reduce motion (app setting or OS) the moves are instant.
- **Finish:** Skip or the last button writes the done flag, so the tour does not return on its own.

## 2. Persistence and triggers

- Done flag: `localStorage` key `app-tour` (same pattern as `panel-sections.ts`: a `KeyValueStore`, every read and write wrapped in try/catch). It is a per-machine convenience, which is what localStorage is for here.
- Show when the flag is absent **and** the library has no events yet (first run). Existing installs that already have events get the flag set silently on upgrade, so they are not surprised. (Default taken; see section 4.)
- Suppressed when `PPT_OUTPUT_DUMP` is set (e2e), the same way the e2e launches already set test flags. The tour's own e2e clears that flag.
- Replay: Settings > About gets a "Show the tour again" button. It clears the flag and opens the tour.
- The Home getting-started checklist stays as it is. The tour does not duplicate it.

## 3. Build

Files (new unless noted):

1. `src/renderer/src/app-tour.ts`: pure step machine. Steps, index, next, back, skip, the done flag. Tests in `app-tour.test.ts` (node environment).
2. `src/renderer/src/components/AppTour.tsx`: the overlay. Renders the card (onboarding) or the scrim, ring and tooltip (spotlights). Measures the target with `getBoundingClientRect`, re-measures on resize and on target change. Focus moves into the card on open and returns to the previously focused control on close.
3. `src/renderer/src/styles/app.css`: tour styles. Card = dialog spec (Panel, 1px Line High border, 6px radius, `--pop-shadow`, 560px). Ring = 2px Text. No accent.
4. `App.tsx`: mount `AppTour` with `tourOpen` in the key guard; compute the show condition on load.
5. `Library.tsx`, `AddWebDialog.tsx`: add `data-testid` to the Add files and Add web page controls if they do not have one.
6. `SettingsDialog.tsx` / About section: "Show the tour again".
7. `e2e/tour.mjs`: fresh user data, no `PPT_OUTPUT_DUMP`. Checks: the cards appear on first run; Space does not take a slide to air while the tour is open (read the session state through the existing test hooks); Skip sets the flag and the tour does not return after a restart; Settings > About replays it. Add to `test:e2e:all`.
8. Docs: `PRODUCT.md` (first-run tour, its keys, replay), `DESIGN.md` (the tour is a dialog-style card and a 2px Text ring; it is the one floating element besides menus and Settings, so the Overview wording "Nothing floats except the Settings dialog and menus" is updated).

Do not touch: the dark palette (Tuning B), the keyboard map outside the tour, the Program output, the Prepare window, English copy outside the tour.
